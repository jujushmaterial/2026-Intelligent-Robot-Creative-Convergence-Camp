# My Contribution

개인 기여도는 팀 결과물을 과장하지 않고 실제 담당 업무를 기준으로 작성한다.

현재 README에는 확정되지 않은 역할을 임의로 넣지 않았으며, 아래 항목을 확인한 뒤 최종 문장으로 바꾼다.

---

## 1. Field Research

확인할 내용:

- 교회·시장 이동 과정에서 담당한 역할
- 운전기사님 또는 어르신 인터뷰에서 직접 질문한 내용
- 인터뷰 기록이나 사진 촬영 담당 여부
- 외국인 노동자가 많다는 점을 처음 발견하거나 문제로 제안한 과정에서의 역할

작성 예시:

```text
장호원 현장조사에 참여해 인터뷰 장소 변경과 주민 인터뷰를 수행했고,
주변 환경 관찰을 통해 새로운 문제 단서를 찾는 과정에 기여했다.
```

실제 수행하지 않은 역할은 사용하지 않는다.

---

## 2. Problem Definition

확인할 내용:

- 외국인 노동자 문제를 제안한 팀원
- 건설현장 안전 문제로 연결한 과정에서 담당한 역할
- 페르소나와 POV 문장 작성 담당
- 사고 통계와 기사 조사 담당

작성 예시:

```text
초기 주차·보행 문제에 머무르지 않고 현장 관찰 결과를 바탕으로
문제 방향을 수정하는 논의에 참여했다.
```

---

## 3. Ideation

확인할 내용:

- `철통이` 명칭 제안 여부
- 현장 스캔 기능 제안자
- Digital Twin 기능 제안자
- 위험구역 프로젝션 기능 제안자
- 보조 발판 또는 고치형 투망 기능 제안자
- 하이브리드 다리·바퀴 구조 제안 과정

작성 예시:

```text
현장 스캔, 위험구역 시각화와 사고 대응 기능을 하나의 이동형 로봇 시스템으로
구체화하는 과정에 참여했다.
```

---

## 4. Prototype and Simulation

확인할 내용:

- 제품 콘셉트 이미지 제작 담당
- 시스템 개략도 제작 담당
- Three.js 시뮬레이션 제작 담당
- 시뮬레이션 수정·검수 담당
- 발표용 캡처와 자료 정리 담당

작성 예시:

```text
아이디어가 작동하는 흐름을 설명하기 위해 제품 시안과 인터랙티브 콘셉트
시뮬레이션 제작에 참여했다.
```

실제 코드를 직접 작성하지 않았다면 `개발했다`보다 `제작 과정에 참여했다`, `기획·검수했다`처럼 정확히 표현한다.

---

## 5. Presentation and Q&A

확인할 내용:

- 발표자료의 담당 페이지
- 발표 대본 작성 여부
- 실제 발표 담당 구간
- Q&A 예상질문과 조사자료 담당
- 팀 발표에서 질문에 답변한 내용

작성 예시:

```text
최종 발표자료와 Q&A 대비자료를 준비하며 기존 로봇, 센서와 Digital Twin 사례를 조사했다.
```

---

## 6. Final Portfolio Version

확정 후 README에는 3~5개 항목만 사용한다.

권장 형식:

```markdown
## My Contribution

- 장호원 현장조사 및 주민 인터뷰 참여
- 현장 관찰을 바탕으로 문제 방향을 수정하는 논의에 참여
- 철통이의 핵심 기능과 사용자 시나리오 구체화
- 제품 시안·시뮬레이션·발표자료 제작 중 실제 담당 영역
- 최종 발표 및 Q&A 준비 중 실제 담당 영역
```

기여도는 길게 나열하기보다 **내가 무엇을 관찰했고, 어떤 판단을 내렸으며, 어떤 결과물을 직접 만들었는지**가 드러나도록 작성한다.
